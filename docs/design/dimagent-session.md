# DimAgent 会话与远程操作设计

本文描述 PC DSH Web 与 Android 的会话设计和 Host 授权边界。客户端逐项协商原生能力，时间线、问答与队列从选中的分支恢复。已实现的接口以[线协议](../protocol.md#dimagent-原生-app-server)为准。

## 打开一个会话

从 Remote 工作区选择器进入 DimAgent，选择工作区、会话和分支。PC 进入 DSH 主会话区域，Android 从会话抽屉进入聊天页。页头显示工作区、会话标题、当前分支和运行状态。用户可以在页头换分支，返回目录时保留原来的列表位置。会话由 Host 上的 DimAgent 管理，客户端只在内存中将原生内容映射给 DSH 展示。映射始终包含 Host、会话和分支，文件引用也在同一工作区内解析。

## 一轮对话怎样显示

| 原生内容 | 用户看到的内容与操作 |
| --- | --- |
| 用户输入 | 按原生顺序显示用户气泡；历史中的图片保留原生文件标识和媒体类型，支持原生附件读取时可点击预览。运行中排队的输入先显示在输入框上方，原生确认消费后再对应到会话记录。 |
| 助手正文 | 按 DSH 聊天页渲染 Markdown、列表、代码块和表格。生成中的同一段文字就地更新。回合结束后，最终答复独立显示，可选择、复制。 |
| 思考、工具调用、结果 | 运行中就地显示当前活动。原生公开的思考内容和工具详情可展开。命令显示摘要、状态及可展开的输出，编辑显示文件与原生提供的变更。未知工具显示原名及可读的输入、结果。已结束的执行过程可折叠，失败原因保留在可见位置。 |
| 审批、提问 | 输入区从原生当前状态恢复待审批与待答问题，可直接允许一次、拒绝，或回答问题。时间线展示原生写入历史的工具调用和结果，包括提问工具的输入与回答。alpha.29 的历史不含已解决审批的决定，重连后只能恢复仍待处理的审批。展开审批能看到完整工具名、参数和理由。单选、多选、多题、自填和拒答遵循原生问题定义，提交时关联原始调用。 |
| 完成、停止、失败 | 按原生结束原因收束本轮，保留已生成正文和工具结果。原生提供用量或起止时间时展示用量或耗时。恢复连接后，更新原来的行、展开位置和滚动锚点。 |

PC 参考 DSH 的 `ChatFlow`、`TurnProcessNodeView`、`AssistantMarkdown` 和公开的审批、问答展示接口。已有插槽可承载的部分直接复用，操作回调由 DimAgent 提供。Android 沿用共享聊天页的回合分组、Markdown、工具行、审批与问答卡片；依赖 Harness 状态的操作显式绑定到当前 DimAgent 分支。两个客户端使用相同的原生身份和排序规则。[移动端聊天组件](../../packages/app-core/src/screens/chat/messages.tsx)

## 历史、实时更新和重连

- 打开分支时先 attach，缓冲实时通知，再读取固定水位的历史。优先使用 daemon 声明支持的 `session.history.display.tail` 展示能力，旧版使用 `latestTurn`。向上滚动沿服务端返回的游标连续补页，维持第一条可见记录的位置。原始事件分页使用原生批次边界。
- 按原生顺序合并已提交事件。文本、思考块使用首个原生事件 ID，并与实时进度的 `textPartId`、`thinkingPartId` 对齐；工具使用原生请求内的调用 ID。历史补齐或跨设备接手时更新同一行。客户端保留有界窗口，可继续按需加载。
- 历史一到即可阅读。分支运行状态、待答问题、待审批和未消费输入分别从原生当前状态恢复，再启用对应按钮。另一台设备已回答或撤回时，本端同步关闭同一请求。提交后断线，重新查询原生结果；结果未明时保留草稿或显示“待确认”。
- 每类操作按 Host 和 daemon 协商的能力开放。只读 Host 保留目录与文本历史，现有交互 Host 保留已支持的操作。PC 本地、PC 远端和 Android 使用相同的操作语义。[原生客户端读取与恢复约定](https://github.com/arcships/dim/blob/v0.1.0-alpha.29/docs/design/clients.md#opening-a-conversation-with-a-bounded-window)

## 会话操作

| 入口 | 目标行为 |
| --- | --- |
| 发送区与队列 | 空闲时发送。运行时分别提供“引导当前运行”和“排队到下一轮”，按原生 TUI 默认优先引导。当前仅支持排队的 Host 继续明确标注“排队发送”。队列展示顺序与状态，可撤回、取回可编辑的文字或将排队项用于引导。停止时把原生仍暂存的消息按顺序取回草稿。“立即中断并发送”另设明确动作，在原生确认停止后将取回的草稿作为一条新消息发送。 |
| 分支与会话 | 进入已有分支、从当前分支末尾开分支、在最后一个已完成回合处分叉会话、选择默认分支和结束指定分支。显示实际操作目标。历史跳转、逐页回溯和导出按所选会话或分支的原生语义提供。重命名等操作由实际可用的 App Server 接口决定。 |
| 模型与上下文 | 显示所选分支实际采用的模型、推理强度和上下文用量。提供原生支持的切换模型、切换 Agent、调整强度、手动压缩。选项与生效时机取自 daemon。 |
| 图片与文件引用 | 支持粘贴或选择图片、长粘贴和工作区 `@` 文件引用。上传使用原生附件标识，附件归属于目标会话。移动设备选取的文件和 Host 工作区内的文件在界面标明来源。 |
| 命令、目标与任务 | 命令菜单列出当前上下文可执行的原生动作。会话目标、后台任务、成员分支与工作流显示实际归属，可查看进度、输出，并选择具体对象停止。普通文字与命令入口分清，避免将不支持的管理命令当提示词发给模型。 |

原生 TUI 的操作与其具体 App Server 能力分别核对。有些命令需要多个读写步骤，队列撤回与消费并发、分支已结束、命令不受当前 daemon 支持时，都应返回可理解的原生结果。[TUI 命令注册表](https://github.com/arcships/dim/blob/v0.1.0-alpha.29/crates/dim-cli/src/ui/commands.rs#L128) · [原生问题与回答契约](https://github.com/arcships/dim/blob/v0.1.0-alpha.29/docs/design/plugins/Questions.md)

## Host 管理范围

PC 和 Android 可以查看已安装的插件、Skill 和 MCP 服务。Host 用户通过本机授权文件逐项开放远程启停，删除授权即生效。启用状态表示 DimAgent 的配置开关。锁定插件、插件提供的 MCP 服务和无效 MCP 配置只读。授权项格式和文件位置见[线协议](../protocol.md#dimagent-原生-app-server)。

插件按逻辑名称切换，影响当前 DimAgent 用户的所有工作区。同一名称下的多个已安装实现共用这项许可，具体实现由 Host 上的原生选择决定。用户及插件提供的 Skill，以及用户级 MCP 服务，也在所有工作区生效。项目 Skill 的稳定 ID 包含项目 Skill 根路径，DimAgent 把该 ID 的开关保存在用户设置中，作用于该工作区的所有分支。项目 MCP 的启用记录绑定工作区的规范路径。

| 操作 | 生效范围与入口 |
| --- | --- |
| 查看已安装项 | 远端展示名称、启用状态及提供的能力。 |
| 启停已获准的项目 | PC 和 Android 在确认前显示项目名、目标状态和原生实际作用范围，例如当前工作区的所有分支，或当前 DimAgent 用户的所有工作区。Host 执行前重新检查当前许可；页面打开后撤销的许可立即生效。 |
| 安装插件、配置运行时、编辑 Hooks 或 MCP 启动命令 | 由 Host 用户在本机操作。可远程启停某个项目的许可仅覆盖该项目的启停。 |
| 扩大授权或持续执行 | 单次工具审批按原生请求处理。远程保存永久规则、授予会话路径权限、配置凭据或创建持续执行的定时任务另行决定。 |

## 验收条件

1. 同一分支在 TUI、PC、Android 上的用户输入、工具调用与结果、最终答复的相对顺序一致。流式正文转为历史后仍只有一份；加载更早消息时保留阅读位置。
2. PC 接到多题问答后断开，Android 可接手回答；PC 重连显示处理结果。审批在两端同时打开时仅一个决定生效，成员分支的请求保持原来归属。
3. 两个分支同时运行时，在其中之一引导、排队、撤回或停止，另一个分支继续执行。当前操作的结果不会落到切换后的 Host 或分支。
4. 用旧 Host 打开同一入口仍可读历史；只支持部分新能力的 Host 仅出现对应操作。真实 daemon 验证原生语义，桌面浏览器和 Android 客户端各自验证滚动、折叠、输入及焦点。
5. PC 与 Android 均可查看已安装项。Host 只允许远程切换 A 时，两端只能切换 A，确认前能看到实际受影响的会话范围。在页面仍打开时由 Host 撤销 A 的许可，再次操作会被拒绝，启用状态保持原值。
